# Analysis of Agentic AI Approaches on an Inventory Scenario

This project compares three approaches to a small stock-management problem: direct prompting, chain-of-thought prompting, and a ReAct-style agent. The scenario I chose is inventory tracking. It is realistic because it contains a mix of questions that require tool lookup and other questions that are best solved by careful reasoning without needing any external source. This makes it a useful example for showing when a model should reason with its own internal logic and when it should use tools to access trusted facts.

The tool-based part of the scenario uses a local inventory table. A warehouse keeps stock counts for several SKUs, each with a product name, current stock, reorder point, target level, and supplier. Some questions can be answered directly from that table, while others do not need any tool at all and instead require arithmetic, sorting, counting, or logical comparison. This mirrors the way real decision-support systems work: a model sometimes needs external facts, sometimes only internal reasoning, and sometimes both.

Direct prompting is the simplest approach. In this setting, the model is asked to answer a question without any explanation. This is useful when the task is brief and the model already has enough context. For the reasoning-only questions, direct prompting can work well if the arithmetic is simple, but it often makes mistakes when the question involves more than one step or when the answer must be exact. In my inventory scenario, a direct prompt can answer small arithmetic questions such as adding stock counts or comparing reorder thresholds, but it is less reliable on tasks that require careful multi-step logic or exact counting. It also cannot access private warehouse data unless that data is included in the question itself, which makes it less suitable for tool-based lookup tasks.

Chain-of-thought prompting is stronger because it asks the model to reason step by step before arriving at a final answer. This makes it better than direct prompting for questions that involve multi-step calculations, ordering, or counting. In my scenario, a CoT question such as computing the average stock, sorting values, or checking which SKU is closest to reorder level is more likely to be answered correctly because the reasoning is visible and the model is guided through the process. The weakness of CoT is that it still does not have direct access to tools unless the prompt itself contains the external facts. It can reason about numbers and structure, but it cannot reliably answer a question that depends on a current inventory record or a lookup table unless the information is given explicitly. This means CoT is strong on internal reasoning but still limited for fact retrieval.

ReAct extends the idea of reasoning with action. The model can think, choose a tool, inspect the result, and then decide how to proceed. In my inventory scenario, the tool-requiring question is about identifying low-stock items, checking which SKUs are at or below their reorder points, and calculating total reorder quantity. A ReAct agent can call an inventory lookup tool, inspect the stock table, and then reason over the result. This is the approach that handles real-world external data best. It does not guess; it looks up the relevant facts, then uses the model to reason over those facts. The limitation of ReAct is that it is more complex and less lightweight than direct prompting or CoT. It requires a tool interface and a loop that decides when enough information has been collected to answer the question. On my scenario, ReAct is the most appropriate choice for stock lookup and reorder decisions, while direct prompting and CoT are more useful for reasoning-only questions.

The table below compares the three approaches on my inventory scenario.

| Aspect | Direct prompting | CoT | ReAct |
|---|---|---|---|
| Reasoning depth | Low to moderate; best on simple arithmetic and short questions | Higher; better for multi-step reasoning and exact calculation | High; combines reasoning with evidence from tools |
| Tool usage | No tool use unless data is embedded in the prompt | No tool use unless data is embedded in the prompt | Uses tools to fetch and inspect inventory data |
| Reliability on multi-step questions | Moderate; can fail when several steps are required | Better than direct prompting, especially for sorting and arithmetic | Strongest when the problem depends on real data and reasoning |
| Transparency | Low; the answer is produced without visible steps | Moderate; the reasoning is explicit in the response | High; Thought, Action, and Observation steps are visible |
| Speed/cost | Fastest and cheapest because it is a single pass | Slower and costlier than direct prompting because it generates more reasoning text | Slowest and most expensive because it may call tools and reason repeatedly |
| Consistency across repeated runs | Variable; same question may produce different results | Better but still can vary if prompts are slightly different | More stable for tool-based tasks, though still dependent on the reasoning loop |

A self-consistency check is useful because it shows whether repeated runs with a stochastic temperature lead to a stable answer. In my project, the script runs the same CoT question five times at a temperature of 0.8 and extracts the final answer from each run. I will fill in the actual results after running the script. The purpose of this check is to see whether the model repeats the same conclusion or whether small differences in randomness lead to different final answers. This is important in real inventory analysis because a decision-support system should not depend on a lucky run of the model when the answer is meant to be reliable.

The suitability analysis for this scenario strongly favors ReAct for the tool-dependent question and CoT or direct prompting for the purely reasoning tasks. For warehouse stock questions that depend on current inventory values, ReAct is the best choice because it can access the relevant table and reason from observed facts. For arithmetic or ordering questions that do not require any external data, CoT is usually more reliable than direct prompting because it shows the model a path to the correct answer. Direct prompting is the simplest and cheapest method, but it is not the best fit for either complex reasoning or fact retrieval in this project. Based on the comparison table, ReAct is the best overall approach for the full scenario, while CoT is the best choice for the pure reasoning subset.

In conclusion, each approach has a clear role. Direct prompting is best for simple questions when the answer is already available in context and the task is short. CoT is the better choice when the model must perform careful multi-step reasoning without any tools. ReAct is the right choice when the task depends on external or private facts that must be retrieved before a final decision can be made. For a realistic inventory scenario like this one, the best system is not a single method alone but a mix of reasoning and tool use, with ReAct used where live data matters and CoT used where the reasoning is purely internal.
